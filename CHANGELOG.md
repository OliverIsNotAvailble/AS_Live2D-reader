# AS Live2D Reader — CHANGELOG

## Maintenance rule

Every code modification must update this CHANGELOG in the **same commit**. Development changes go directly to `main`; a separate final-version branch is created only when a whole version series is closed. Include concrete changes, changed files, verification and known issues. The README is set up once and does not need editing for routine updates.

## 0.1.9 — 2026-10-13 — Fix rotated Live2D invisible rectangular clipping

- Fixed the visible diagonal crop shown by the user at e.g. +30°. V0.1.8 first rasterized Cubism to an unrotated, **same-size offscreen FBO** and then rotated those already-clipped pixels. Areas of the character outside the source FBO could never appear in the final frame, leaving artificial straight diagonal cut lines inside the red frame.
- Replaced intermediate texture rotation with **Cubism's built-in native MVP rotation before rasterization**. Verified the exact pinned upstream live2d-py **v0.7.0.4** `LAppModel.Rotate(degrees)` and `Model.Rotate(degrees)` methods, and `MatrixManager::Rotate` degree conversion. UI remains clockwise-positive: `+30°` calls native `Rotate(-30°)`. The GPU now clips only at the *real final viewport*, not at an extra hidden unrotated rectangle.
- Removed the former rotation shader, its extra preview/export FBOs and its additional render/compositing pass. Preview draws the Live2D rig directly on the final Qt framebuffer, on top of the stationary background; offscreen MP4/WebP/PNG capture likewise draws the rotated native model directly into its final-resolution framebuffer. This also eliminates the associated extra GPU memory/rendering work.
- Kept `Rotation`, `Reset rotation (0°)`, `Fit rotated canvas inside frame`, Zoom, X/Y and model-profile persistence unchanged. The optional fit now multiplies the native model scale, using the *actual active render resolution* for preview or export. After capture, the preview resolution, zoom, offset and angle are restored.
- Rotation does **not** modify source `.moc3`, motions, textures or background. Some clipping is still expected when the model extends past the actual red output frame; the bug was clipping *inside* that frame.
- Regression tests now assert actual installed native `Rotate` availability, correct clockwise sign, aspect-fit scale, direct unmasked preview/export draw paths and post-export transform restoration. Removed tests that incorrectly expected an intermediate FBO.
- Version updated to **0.1.9**. Files: `as_live2d/viewer.py`, `as_live2d/window.py`, `as_live2d/__init__.py`, `tests/test_rotation.py`, `CHANGELOG.md`. No README edits, no branch; committed directly to main.
- Verification: Windows Python 3.10 CI pending. Confirm visually in the user's GPU preview and MP4/WebP export with +30° rotation.

## 0.1.8 — 2026-10-13 — Live2D clockwise rotation and framing

- Added `Camera & frame > Rotation` in degrees from **-180° to +180°**, default 0°. Positive angles rotate the rendered character **clockwise/right** (e.g. +30°), negative angles rotate counterclockwise/left. Added `Reset rotation (0°)` and optional `Fit rotated canvas inside frame` to scale the rotated model layer down without changing the output frame or background. The existing Zoom, X and Y fields remain available for manual alignment.
- Model-only GPU compositing: draw Cubism to a **transparent OpenGL framebuffer** at native preview resolution, then rotate/sample the character layer in a pixel-space fragment shader using premultiplied-alpha blending. The background image/color remains stationary. This avoids altering MOC3 rigs, parameters, motion curves or source textures, and avoids CPU image readbacks during normal interactive playback.
- Export path reuses the same rotation shader and degree/fit settings for both existing black/white alpha captures before MP4/WebP/PNG encoding. Export composition and preview use separate reusable FBOs sized independently for display and output, preventing FBO reallocation on every frame. Unrotated 0° previews/exports use their previous direct-render path.
- Rotating in pixel coordinates (rather than raw normalized device coordinates) prevents stretching/skewing on wide 16:9 and portrait frames. The optional frame-fit factor is computed from the rotated rectangle dimensions and is applied identically in preview and export.
- Per-model profile `*.as-reader.json` now persists `rotation_deg` and `fit_rotation`; loading a new model without a saved profile resets rotation to 0°, rather than inheriting the previous model's angle. The profile continues to preserve the independent preview motion, export checklist, camera, backgrounds and Parts settings.
- Added `as_live2d/rotation.py` with tested aspect-aware geometry; `tests/test_rotation.py` validates clockwise direction, portrait/wide fit, reset/profile isolation, OpenGL preview routing and export readback routing without a graphics driver.
- Files: `as_live2d/rotation.py` (new), `as_live2d/viewer.py`, `as_live2d/window.py`, `as_live2d/__init__.py`, `tests/test_rotation.py` (new), this `CHANGELOG.md`. README unchanged; direct changes to `main` only.

## 0.1.7 — 2026-10-12 — Correct native Parameter setter for pinned live2d-py

- Fixed the real user report: `Preview paused after playback error: 'live2d.Model' object has no attribute 'SetParamByIndex'` from v0.1.6. The public `LAppModel` wrapper and its internal `live2d.Model` both lack that method in the installed **live2d-py 0.7.0.4** runtime.
- Verified the exact v0.7.0.4 tag of upstream `Wrapper/V3/PyModel.cpp` and `package/live2d/v3/_v3cpp.pyi`: the actual native method is **`SetParameterValue(index, value, weight=1.0)`**. `SetParamByIndex` exists only on a later version of upstream, which previous development accidentally treated as the installed API.
- Updated the per-frame Parameter evaluator to call `SetParameterValue` on `self.model._model`; kept the no-invalid-motion-group change and one-error-per-playback guard from v0.1.6. All preview and MP4/WebP/PNG export frames use the corrected parameter application.
- Tightened regression tests with `spec_set` mocks and added a direct API contract test that imports the real `live2d.v3._v3cpp.Model` extension installed by `requirements.txt`. This prevents the previously misleading fully dynamic mocks from allowing a nonexistent setter again.
- Window/package version advanced to **0.1.7**. Files: `as_live2d/part_visibility.py`, `as_live2d/window.py`, `as_live2d/__init__.py`, `tests/test_parameter_motion.py`, this changelog. README untouched; changes committed directly to `main`.
- Validation note: first Windows run `38330057919` confirmed the real live2d-py 0.7.0.4 `Model.SetParameterValue` API contract but flagged an incomplete `spec_set` mock in the blink assertion. Updated that test mock to include `UpdateBlink`; native playback code unchanged. ## 0.1.6 — 2026-10-12 — Repair frozen preview and repeated error spam

- Investigated the user's real 1,033-line console log (about 76 KB): the same `AttributeError: 'LAppModel' object has no attribute 'SetParamByIndex'` was printed **115 times** and the native Cubism log `motion(__ASREADER_FIXED___0) has no file attached` appeared **114 times**. This is a program regression introduced by v0.1.5, not missing animation data.

The previous tests used unrestricted `Mock` objects that silently accepted methods absent from the actual wrapper; tests now assert the native call explicitly.

For interleaved Unity-exported motion curves, the Reader now uses its own per-frame Parameter and PartOpacity evaluators exclusively; this requires no native `LoadExtraMotion` registration and cannot loop attempting to play a missing fixed group. Correctly grouped motion files continue using the original native motion group, with direct Parameter evaluation retained as a safety net.

Source `.motion3.json` and `.moc3` files remain untouched. The older `motion_runtime.py` normalizer is retained as an optional utility/test, but is not invoked in normal playback.
- Added a fail-safe for Qt preview timer errors: one exception stops that playback and emits a concise message to the GUI log instead of printing hundreds of full tracebacks at 60 FPS. Export errors continue to be handled by their export controller.
- Regression tests cover the real `LAppModel`/native-method boundary, manual playback for a mixed-target motion with **no** `LoadExtraMotion` or invalid group, and one-time timer failure handling. No copyrighted game files uploaded to this repository.

## 0.1.5 — 2026-10-12 — Fix static motions that only blink

- Investigated the provided `ahcy1_H_Cumshake.motion3.json` and `ahcy1_H_penis_putin.motion3.json` against the previously supplied `Char100_Pose3.moc3`. Both contain 84 distinct animated Parameter curves; **all 84 parameter IDs are present in the source MOC3**. They also contain 59 and 22 PartOpacity curves, respectively. Therefore these files are not still images and the apparent motionless preview is not explained by missing parameter IDs.
- Root cause found in live2d-py native `PyModel_UpdateMotion` binding (0.7.0.4): it invokes native animation but always returns Python `None`. The Reader had treated that return as a boolean and was applying automatic eye blink even while motion playback was active. It now checks `IsMotionFinished()` instead of relying on that broken return value; authored eye-opening curves take priority over auto blink.
- Implemented independent per-frame evaluation of **Parameter** curves alongside existing **PartOpacity** handling. `read_motion_tracks` parses the original motion file once per selection; parameter indices are resolved once from `GetParamIds()` and mapped to `SetParamByIndex()` on every frame. This guarantees the rig receives the authored interpolated changes even if the native motion loader or manager fails to apply them.
- Parameter fallback is applied after native Load/Update/SaveParameters and expression/drag updates but before breath, physics and pose, so downstream deformation can use current motion values. Applies equally to fast GPU preview and offscreen MP4/WebP/PNG frames. The original Cubism/Unity/game files remain unchanged; existing temporary sorted motions, Parts controls and background render are preserved.
- New console diagnostic reports number of Parameter curves matched to MOC3 when a motion starts, with a warning if none match. Supports all Cubism segment types already handled by the existing motion curve evaluator.
- Added `tests/test_parameter_motion.py` covering interleaved Parameter/PartOpacity data, native frame interpolation and a mocked active native motion returning `None`, which must **not** suppress parameter movement or cause auto blink to override authored eye curves. Does not store any proprietary game assets in this public repository.
- New version **0.1.5** (window and package). Files changed: `as_live2d/part_visibility.py`, `as_live2d/viewer.py`, `as_live2d/window.py`, `as_live2d/__init__.py`, `tests/test_parameter_motion.py` (new), this changelog. README untouched; changes committed directly to `main`.
- Verification: **Windows Python 3.10 CI passed** (syntax, manifest, PartOpacity, Parameter playback regression tests with mocked `UpdateMotion() -> None`, Qt GUI construction): https://github.com/OliverIsNotAvailble/AS_Live2D-reader/actions/runs/38323034716. Real-time animation motion and MP4/WebP output using the user's assets still require Windows GPU testing.

- Reproduced the cause from the attached `ahcy1_I_clothes_turnOff.motion3.json`: the clip hides `head_1` throughout its nine seconds but never sets `head_2` visible. If a preceding clip leaves that alternative head hidden, a standalone export renders a headless figure. The transition is state-dependent; this is not a missing texture or MOC3 defect.
- Confirmed all three supplied idle/transition motions contain interleaved Target groups (Parameter → PartOpacity → Parameter → PartOpacity). The Native Cubism motion evaluator traverses these target classes in contiguous order and can fail to apply *both* later Parameter and PartOpacity tracks. The previous post-pose PartOpacity fix covered visibility only; skipped native Parameter curves could still deform the model incorrectly.
- Added `motion_runtime.py` to create on-demand normalized temporary copies of interleaved `.motion3.json` files. Stable-sorts curves into Model → Parameter → PartOpacity while preserving every individual curve, segment, Meta value and UserData. Native runtime loads these corrected files via `LAppModel.LoadExtraMotion`, and both preview and offscreen export use the corrected native motion. It caches each motion and cleans temporary files when switching models/closing. Source Unity/game files are **never modified**.
- Added **Independent motions (reset Parts)** toggle, enabled by default. At the beginning of each preview/export clip it sets part visibility to a known 100% baseline, then applies the active motion's own PartOpacity curves (and any manually saved overrides). This avoids invisible parts leaking from the prior clip. Turn it off when intentionally chaining transitions that depend on the preceding animation's state; because the runtime doesn't expose the original MOC part defaults, baseline 100% may expose unspecified alternative parts in some rigs, adjustable using the Parts tab.
- Persists the new toggle in each model's AS Reader profile under `standalone_parts`. Existing profiles default to independent mode.

## 0.1.3 — 2026-10-12 — PartOpacity motion support and alternate mesh visibility

- Diagnosed the uploaded `Char100_Pose3.moc3`, `Char100_Pose3.model3.json` and the two `ahcy1_I_idle_*.motion3.json` examples **without uploading these game files to this public repository**. The MOC3 contains both `head_1` and `head_2` parts. Both idle motions explicitly set `head_1` PartOpacity to 0, but their curve ordering is mixed: 20 Parameters, one PartOpacity, 64 more Parameters, then 14/18 more PartOpacity curves. The Native SDK expects a Model → Parameter → PartOpacity sequence and may not evaluate the later tracks.
- Added pure-Python motion `PartOpacity` evaluation independent of Native SDK curve iteration. Supports linear, Bézier, stepped and inverse-stepped Cubism segments. Curves are parsed once per selected motion, not per render frame.
- `Live2DViewer` now enumerates Cubism part IDs after loading a model and applies the currently active motion's part opacities *after* the native motion/physics/pose update on each preview/export frame. This hides intentional alternate heads, arms, legs and clothing when their motion contains explicit hide tracks. Reports interleaved motion targets to the console. Original `.moc3`, `.model3.json`, PNG and `.motion3.json` files remain untouched.
- Added **Parts** tab with searchable part IDs and tri-state visibility controls: Auto (motion controlled), Show and Hide. Manual visibility overrides win over motion curves and are saved in the existing model-specific profile under `part_overrides`. Reset restores motion-controlled state, and switching models resets transient overrides before applying that model's profile.
- Motions and exports pass their original motion JSON path and duration to the viewer; the same opacity handling applies to preview and offscreen frames. Export is still processed in the encoder worker.
- Note: mixed ordering can also prevent the native SDK from applying **Parameter** curves after the first PartOpacity. This version safeguards part visibility; reordering `Model`, `Parameter`, `PartOpacity` in the actual motion files remains recommended for complete motion fidelity. This change does not silently rewrite game files or model rigs.
- Added unit tests for the four segment types, malformed data and detection of interleaved motion targets. Version title/package updated to 0.1.3.
- Files: `as_live2d/part_visibility.py` (new), `as_live2d/viewer.py`, `as_live2d/window.py`, `as_live2d/__init__.py`, `tests/test_part_visibility.py` (new) and this `CHANGELOG.md`. README untouched. Direct commit to `main`, no new branch.

## 0.1.0 — 2026-10-10 — Initial standalone Live2D Reader

- New standalone Python / PySide6 / live2d-py application in `AS_Live2D-reader`; no changes to FBX Reader or AS19 repositories.
- **Open multiple models in one window:** reuses the same OpenGL widget/context and destroys the previous Cubism renderer before creating the next; removes the old Qt splitter `None.deleteLater` failure path. Failed model loading is surfaced as an error without keeping a misleading old model selected.
- **Native GPU preview:** native Cubism draw straight to QOpenGLWidget at an approximately 16 ms timer interval, with separate motion update and draw. Normal preview does **not** read GPU pixels, perform black/white alpha passes, or convert every frame to a QImage/NumPy frame. Provides loop, pause/play, wheel zoom, pan, camera reset and live FPS indicator.
- **Independent export resolution:** QOpenGLFramebufferObject with two-pass black/white alpha reconstruction only during export; restores the preview's framebuffer, viewport and model resolution afterward.
- **Per-model validation:** parses model3.json FileReferences; resolves MOC, textures, motions, physics, expressions and other declared files; Files tab displays missing references. Models with zero motions can be viewed. Model manifests are never modified.
- **Export engine:** select motions and export MP4 (H.264), animated WebP with alpha, PNG sequences or MP4+WebP. Supports motion FPS or override, output resolution, color/image/transparent background and WebP quality. FFmpeg or PNG encoding runs on a bounded-queue QThread, avoiding writing video pipes on the GUI thread. Temporary outputs are committed only after success and removed on error/cancel.
- **Profile:** per-model `*.model3.json.as-reader.json` with camera, output format, background and selected motion settings; saved atomically, without touching Cubism source files.
- Initial README, requirements, `main.py`, modules under `as_live2d`, Python model-manifest tests and GitHub Actions CI.
- Files: `README.md`, `CHANGELOG.md`, `.gitignore`, `requirements.txt`, `main.py`, `as_live2d/__init__.py`, `as_live2d/model.py`, `as_live2d/viewer.py`, `as_live2d/encoder.py`, `as_live2d/window.py`, `tests/test_model.py`, `.github/workflows/validate.yml`.
- Verification: initial Windows Python 3.10 source compilation and manifest tests **passed**: https://github.com/OliverIsNotAvailble/AS_Live2D-reader/actions/runs/38106421076. Native Live2D GPU rendering/export still requires actual Windows model testing; 60 FPS is a target, not a guarantee.
- Current limits: no live editing of Cubism rig geometry or part opacity; Expressions panel lists referenced expression files, but does not yet modify active expression playback. FFmpeg is a separate installation. No proprietary Cubism Core binary distributed.
