# AS Live2D Reader — CHANGELOG

## Maintenance rule

Every code modification must update this CHANGELOG in the **same commit**. Development changes go directly to `main`; a separate final-version branch is created only when a whole version series is closed. Include concrete changes, changed files, verification and known issues. The README is set up once and does not need editing for routine updates.

## 0.1.20 — 2026-11-10 — ArtMesh hidden com PNG 1×1 (sem atlas gigante e sem inverter V)

- Substituída a geração de PNGs 4K/2K de atlas inteiro por **UMA textura transparente de 1×1 pixel**. Ao desmarcar uma ArtMesh, somente seu índice de textura na **cópia temporária de MOC3** aponta para essa página totalmente vazia. As demais ArtMeshes seguem apontando para as texturas originais, mesmo se suas UVs se sobrepuserem. Ao marcar novamente, o MOC3 temporário é refeito diretamente dos bytes originais e a imagem volta; a exportação usa o mesmo renderizador do preview.
- Não é gerado MOD nem atlas editado. O programa reutiliza no máximo 2 MOC3 temporários e 2 manifests alternados, evitando centenas de arquivos; o cache é limpo ao fechar. MOC3 original não é alterado.
- **Correção de segurança:** a versão anterior gerava MOC3 inválido ao reserializar todo o binário via py-moc3. A nova abordagem altera só 4 bytes por ID da ArtMesh no arquivo temporário. Antes disso verifica endian, mapeamento de todos os índices de textura contra o binário original, intervalos e limites de seção. Preserva byte-a-byte cabeçalho, tabela de offsets, keyforms, UVs e geometria.
- O checkbox **Inverter V** no editor de ArtMesh agora inicia **DESMARCADO**. Este recurso de ocultação não utiliza UVs nem inversão V: uma textura transparente de 1×1 funciona independentemente das coordenadas.
- Testes para patch binário pontual, rejeição de offsets inconsistentes, tamanho único 1×1 do PNG, número limitado de arquivos e preservação integral dos assets originais. README inalterado.
- **Pendente:** validar na engine Cubism no Windows com o modelo real que falhava. Essa verificação é indispensável antes de declarar a ocultação completamente resolvida.

## 0.1.19 — 2026-11-10 — Corrigido crash de MOC3 temporário inválido

- Corrigido travamento fatal `csmHasMocConsistency: Header section is invalid`: versão anterior gerava um MOC3 temporário reserializado pelo py-moc3 que era aceito pelo parser Python, mas rejeitado pelo Cubism Core. **O renderizador nunca mais cria, regrava ou reserializa MOC3 para alternar ArtMeshes**: o manifest temporário agora aponta para o arquivo MOC3 original, byte-a-byte.
- Checkboxes de ArtMesh alteram automaticamente uma PNG temporária da página de textura, limpando apenas os triângulos UV da ArtMesh desmarcada via QImage/QPainter. Preview e exportação continuam no mesmo Live2DViewer; ao remarcar, a PNG temporária é regenerada ou o atlas original é reutilizado. Processamento de imagem fica em QThread e não gera mod permanente.
- O estado `SHOW` não força uma peça originalmente desabilitada no MOC3: uma imagem não tem como fazer um Drawable inativo voltar a renderizar. Nesses casos o comando falha com mensagem sem reescrever fontes. A operação também **não pode isolar ArtMeshes que compartilham exatamente os mesmos pixels UV**: nessas regiões, ocultar uma pode ocultar a outra. Esta limitação é exibida na interface.
- Novos testes verificam apagamento de somente um triângulo em atlas, referência ao MOC3 original (sem reserialização), preservação dos assets originais e erro para ArtMesh não encontrada. `live_mesh_preview.py`, `mesh_visibility_controller.py`, `window.py`, testes e versão atualizados. README não alterado. Requer validação manual no Windows com o MOC3 que reproduziu o crash.

## 0.1.18 — 2026-11-10 — Checkbox ArtMesh direto no preview e exportação

Nada é salvo na pasta de mod e o cache é excluído no fechamento. Demais peças do mesmo Part, parâmetros, UVs e camadas permanecem inalterados. Marcar de novo restaura a visibilidade e opacidade originais (cópia reconstruída desde o MOC3 fonte).
- Exportação bloqueada enquanto o cache de preview não está sincronizado, para não gerar frames com peças que deveriam estar ocultas. Controles de Part continuam funcionando independentemente, inclusive após recarga do renderizador.
- Criados `live_mesh_preview.py`, `mesh_visibility_controller.py`, `test_live_mesh_preview.py`. Atualizados `mesh_visibility.py`, `window.py`, testes de visibilidade e `__init__.py`. README não alterado. **Pendente:** validar o renderizador com um MOC3 real e máscaras/clipping; a atualização pode exigir recarga curta do modelo.

## 0.1.12 — 2026-11-10 — Mod ArtMesh / atlas editor with independent model copies

- Added **Meshes → Editar ArtMesh / textura → pasta mod**, a modal Qt editor. A native `live2d-py 0.7.0.4` ArtMesh ID list helps identify individual Cubism pieces, and the user selects an atlas texture to retouch. Editing tools: transparent brush, rectangle erase, image zoom/fit, undo/reset per texture, export a working PNG to an external editor and re-import an edited PNG at exactly the same dimensions. The modified atlas is visualized before saving.
- **Truthful scope:** this changes alpha pixels in one or more texture atlas pages; it does **not** rewrite the packed `.moc3` geometry, vertex coordinates, UVs, deformers, triangle topology, or the physical ArtMesh boundary. Pinned `live2d-py 0.7.0.4` exposes `GetDrawableIds` and `HitDrawable`, but does not expose safe mutable per-Drawable vertices/UVs or a method to compile a new MOC3. ArtMesh ID selection does not automatically map that mesh's UVs to the atlas; the user identifies its area manually. Shared texture/UV regions can be affected in multiple drawables.
- Clicking **Salvar cópia em mod/ e abrir** creates `<original model folder>/mod/<model>_mod_001/` with its own `*.model3.json`, original `*.moc3` copy, all referenced textures (including unedited pages), Physics, Pose, DisplayInfo, UserData, Motions, Expressions and motion Sound files. Relative manifest references are rewritten to local copies, edited atlas pages use transparent PNGs, and `MOD_INFO.txt` documents the source and scope. No original files or prior mods are overwritten; subsequent saves increment the suffix. Re-editing a mod stays under the same mod/ folder, rather than nesting mod/mod.
- Upon completion, Reader opens the newly created model from `mod` so the user can preview/export animations without touching the original. Existing original model profiles, fixed export folder, preview playback and rendering stay unchanged. This is strictly optional.
- Added `as_live2d/texture_mod.py`, `as_live2d/texture_mod_dialog.py`, `tests/test_texture_mod.py`, updated `as_live2d/window.py`, version in `__init__.py`, and this changelog. README untouched.
- CI includes syntax compilation, Qt/headless tests for alpha erasing, undo replay, standalone model dependencies, no source mutation, unique mod folders, rejection of mismatched atlas size, and GUI construction. Real GPU/model validation remains recommended before adopting a patch.

## 0.1.9 — 2026-10-13 — Fix rotated Live2D invisible rectangular clipping

- Fixed the visible diagonal crop shown by the user at e.g. +30°. V0.1.8 first rasterized Cubism to an unrotated, **same-size offscreen FBO** and then rotated those already-clipped pixels. Areas of the character outside the source FBO could never appear in the final frame, leaving artificial straight diagonal cut lines inside the red frame.
- Replaced intermediate texture rotation with **Cubism's built-in native MVP rotation before rasterization**. Verified the exact pinned upstream live2d-py **v0.7.0.4** `LAppModel.Rotate(degrees)` and `Model.Rotate(degrees)` methods, and `MatrixManager::Rotate` degree conversion. UI remains clockwise-positive: `+30°` calls native `Rotate(-30°)`. The GPU now clips only at the *real final viewport*, not at an extra hidden unrotated rectangle.
- Removed the former rotation shader, its extra preview/export FBOs and its additional render/compositing pass. Preview draws the Live2D rig directly on the final Qt framebuffer, on top of the stationary background; offscreen MP4/WebP/PNG capture likewise draws the rotated native model directly into its final-resolution framebuffer. This also eliminates the associated extra GPU memory/rendering work.
- Kept `Rotation`, `Reset rotation (0°)`, `Fit rotated canvas inside frame`, Zoom, X/Y and model-profile persistence unchanged. The optional fit now multiplies the native model scale, using the *actual active render resolution* for preview or export. After capture, the preview resolution, zoom, offset and angle are restored.
- Rotation does **not** modify source `.moc3`, motions, textures or background. Some clipping is still expected when the model extends past the actual red output frame; the bug was clipping *inside* that frame.
- Regression tests now assert actual installed native `Rotate` availability, correct clockwise sign, aspect-fit scale, direct unmasked preview/export draw paths and post-export transform restoration. Removed tests that incorrectly expected an intermediate FBO.
- Version updated to **0.1.9**. Files: `as_live2d/viewer.py`, `as_live2d/window.py`, `as_live2d/__init__.py`, `tests/test_rotation.py`, `CHANGELOG.md`. No README edits, no branch; committed directly to main.
- Verification: Windows Python 3.10 CI **passed** (Python syntax, native Cubism rotation API contract, geometry/preview/export/profile regressions and GUI smoke): https://github.com/OliverIsNotAvailble/AS_Live2D-reader/actions/runs/38502930578. Visual confirmation on the user's GPU and a real MP4/WebP export with +30° remain necessary.

## 0.1.8 — 2026-10-13 — Live2D clockwise rotation and framing

- Added `Camera & frame > Rotation` in degrees from **-180° to +180°**, default 0°. Positive angles rotate the rendered character **clockwise/right** (e.g. +30°), negative angles rotate counterclockwise/left. Added `Reset rotation (0°)` and optional `Fit rotated canvas inside frame` to scale the rotated model layer down without changing the output frame or background. The existing Zoom, X and Y fields remain available for manual alignment.
- Model-only GPU compositing: draw Cubism to a **transparent OpenGL framebuffer** at native preview resolution, then rotate/sample the character layer in a pixel-space fragment shader using premultiplied-alpha blending. The background image/color remains stationary. This avoids altering MOC3 rigs, parameters, motion curves or source textures, and avoids CPU image readbacks during normal interactive playback.
- Export path reuses the same rotation shader and degree/fit settings for both existing black/white alpha captures before MP4/WebP/PNG encoding. Export composition and preview use separate reusable FBOs sized independently for display and output, preventing FBO reallocation on every frame. Unrotated 0° previews/exports use their previous direct-render path.
- Rotating in pixel coordinates (rather than raw normalized device coordinates) prevents stretching/skewing on wide 16:9 and portrait frames. The optional frame-fit factor is computed from the rotated rectangle dimensions and is applied identically in preview and export.
- Per-model profile `*.as-reader.json` now persists `rotation_deg` and `fit_rotation`; loading a new model without a saved profile resets rotation to 0°, rather than inheriting the previous model's angle. The profile continues to preserve the independent preview motion, export checklist, camera, backgrounds and Parts settings.
- Added `as_live2d/rotation.py` with tested aspect-aware geometry; `tests/test_rotation.py` validates clockwise direction, portrait/wide fit, reset/profile isolation, OpenGL preview routing and export readback routing without a graphics driver.
- Files: `as_live2d/rotation.py` (new), `as_live2d/viewer.py`, `as_live2d/window.py`, `as_live2d/__init__.py`, `tests/test_rotation.py` (new), this `CHANGELOG.md`. README unchanged; direct changes to `main` only.
